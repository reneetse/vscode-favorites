# Favorites 1.16.0 使用说明

## 排序

点击收藏视图顶部的“选择排序方式”，可选择名称升序、名称降序、最近修改优先、最早修改优先、文件类型和手动排序。设置对收藏顶层和展开的文件夹内容生效；手动排序下，顶层保留收藏顺序，文件夹内部按名称升序显示。

除手动排序外，文件夹优先。上移、下移、置顶和置底以当前可见顺序为基准，操作后切换为手动排序。修改时间取文件系统的上次修改时间，不是上次打开时间；保存文件或点击刷新后更新。名称按自然数字顺序排列，例如 `note2.md` 在 `note10.md` 前面。

## 新建子文件夹

右键收藏中的文件夹或展开后的子文件夹，选择“新建子文件夹”。右键文件时，在该文件所在目录中新建。只接受单个文件夹名称，不接受路径跳转；重名时提示，不覆盖已有内容。

## 将文件移回 jack

1. 在收藏视图多选要移动的文件，右键选择“移动到文件夹…”，选择实际的 `jack` 目录。
2. 也可以把多选项直接拖到收藏视图中的 `jack` 文件夹或其子文件夹上。
3. 操作会真正移动磁盘文件，并更新所有收藏分组中的路径；移动整个文件夹时，内部文件的收藏路径一并更新。

旧版本拖放仅调整收藏列表，不会将磁盘文件放入目标目录，这是批量拖回 `jack` 看起来不生效的原因。新版在收藏视图内部拖到文件夹执行真实移动；拖到文件或空白位置仍然用于收藏调序或添加快捷项。从资源管理器或编辑器直接拖入只添加收藏，不移动磁盘文件：部分旧版 VS Code 的外部拖放不提供完整目录选择，需先添加收藏，再在收藏视图中选择并移动。

同名目标或多个同名源文件会在整批操作开始前拦截，不覆盖文件。批量选中的名称仅大小写或 Unicode 规范化形式不同，也会保守拦截，可改为逐个移动。文件已在目标目录时跳过；同时选择父文件夹和内部文件时只移动父文件夹一次。文件移动使用 VS Code 工作区编辑，可通过“撤销”恢复。若运行期间发生权限、磁盘或其他错误，批次可能部分完成；提示会尽量核实并列出已完成数量和路径，已完成项目的收藏路径会同步更新。中断的批次不保证生成撤销记录，请检查源、目标目录后再重试。

支持当前 VS Code 主机文件系统和 Remote SSH。源与目标须处于相同文件系统及远端连接中；普通网页链接和其他虚拟资源不能执行文件管理。

## 语言

打开 VS Code 设置，搜索 `favorites.language`：

| 值 | 行为 |
| --- | --- |
| `zh-CN` | 中文，默认值 |
| `en` | English |
| `auto` | 跟随 VS Code，中文界面使用中文，其他语言使用英文 |

菜单、提示、收藏视图标题及当前分组提示随设置更新，无需重载。现有分组名称和收藏内容不改名。

## 安装

安装包为 `releases/vscode-favorites-1.16.0.vsix`，其他环境已克隆仓库时无需重新编译。在仓库 `master` 分支、目标 VS Code 窗口的终端中执行：

```sh
git pull --ff-only
code --install-extension ./releases/vscode-favorites-1.16.0.vsix --force
```

也可从扩展面板选择“从 VSIX 安装”。安装后执行 `Developer: Reload Window`，确认版本为 `1.16.0`。Remote SSH、WSL 和容器需分别安装到对应目标环境。配置格式兼容旧版本，无需迁移收藏。维护者重新打包使用 `npm run build`。

## 验证边界

回归命令为 `npm test`，通过 VS Code API 适配器操作真实临时文件和临时 Git 仓库，检查批量移动、目录创建、冲突、部分失败、收藏路径更新、排序和语言切换。类型检查使用 `npm run check-types`。

这些检查不等于真实 VS Code 界面验收。安装后仍应在临时文件上确认多选拖放、目录选择器、菜单语言、撤销和剪贴板操作；不会自动搬动用户工作区里的实际文件。
